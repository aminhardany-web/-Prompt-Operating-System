## Classification rules
A real prompt must contain executable instructions or a prompt-template structure intended to guide model behavior.
A response/report/lesson-plan is not automatically a prompt.
A mention of a prompt is not a prompt.
A repeated exact text is not a new record.
A meaningfully changed text gets a new/versioned record with lineage.

## Reconstruction order
SOURCE TEXT → SOURCE HASH → TITLE/CATEGORY → USER INTENT AS EXPLICITLY WRITTEN → CONTEXT → INPUTS → CONSTRAINTS → EXECUTION STEPS → OUTPUT CONTRACT → QUALITY GATES → FAILURE CONDITIONS → RETRIEVAL KEYS → TEST PLAN.

## Optimization order
1. Preserve source unchanged.
2. Identify the job-to-be-done.
3. Remove ambiguity without deleting source meaning.
4. Separate role/context/task/output.
5. Convert vague requests into measurable output requirements where source permits.
6. Add explicit evidence/verification gates when required by the task.
7. Add failure/rejection criteria.
8. Add examples only where they increase repeatability.
9. Define evaluation criteria.
10. Link every derived version to its parent Source Prompt.

## Release gate
DERIVED_OPTIMIZED is not production-ready until task-specific evaluation and runtime testing exist.

## Non-negotiable
No source prompt is overwritten. No historical evidence is discarded. No completeness claim is made while unresolved discovery queues or inaccessible source surfaces remain.
